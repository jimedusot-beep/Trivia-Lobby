Protocol Outline (WebSocket messages)

Client → Server
	•	create_room { hostId, deckId }
	•	join_room { roomCode, playerId, name }
	•	rejoin_room { roomCode, playerId }
	•	start_game { roomCode }
	•	submit_answer { roomCode, playerId, questionInstanceId, letter }

Server → Client
	•	room_created { roomCode }
	•	lobby_update { players[] }
	•	game_started { deckMeta }
	•	question_start { questionInstanceId, index, prompt, choices, serverStartTs, timeLimitMs }
	•	answer_result { questionInstanceId, correctLetter, leaderboard[] }
	•	sync_snapshot { roomState, currentQuestion, leaderboard, timeRemainingMs }
	•	error { code, message }

Key correctness rules
	•	Server is authoritative on timer/scoring because browsers throttle timers in background (MDN Page Visibility API)
https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API
	•	Answer submissions must be idempotent by (playerId, questionInstanceId) (prevents double credit).
	•	Heartbeat pings terminate dead clients (ws ping/pong guidance)
https://github.com/websockets/ws
