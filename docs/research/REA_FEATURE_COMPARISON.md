## Shared architecture and boundaries (DESIGN)

Use the current React/TypeScript/Express/PostgreSQL/WebSocket stack. Public routes consume a curated, versioned demo catalog and device-local progress; private routes retain account and owner checks. Live guest hosts receive room-scoped capability authority only over demo rooms. Pure question/lesson/party reducers feed distinct presentation adapters. No raw DB entity becomes a public payload by default. No private content becomes public when a user signs out. Signing in does not silently upload device progress.

Proposed public contract namespace `/api/public/demos` is separate from `/api/decks`, `/api/library`, `/api/study` and private question/report APIs. Immutable catalog IDs cannot be used as database deck IDs. Storage schema validation is mandatory at import and resume boundaries. Do not promise permanent or cross-device storage for local guest data; account-backed private saving remains separate.

## Cross-cutting tests and performance requirements (DESIGN)

The assignment owner must run the relevant existing regression suite plus new behavioral tests, not merely add route snapshots. A clean-session browser must complete demo play and learning without registration; the same browser must still receive unauthorized responses for private source/history/deck APIs. Test duplicate events, deadlines, missing content, unavailable storage and reconnect at the boundary that owns them. Automated accessibility checks must be supplemented by keyboard and screen-reader journeys; reduced motion and non-sensor alternatives are required.

Use topic budgets with a documented device/server, production build, network assumptions, sample size and p95 measurements. Failed budgets block the corresponding feature claim; thresholds are adjustable only with a documented reason. Do not optimize or load-test unrelated surfaces in this research PR.
