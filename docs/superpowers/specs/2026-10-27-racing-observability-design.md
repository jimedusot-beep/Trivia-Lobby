# Failure logging and live racing measurements

The October 27 user request authorizes improving failure logging and measuring live racing delays before adding games. Existing recovery catches hide checkpoint failures from Render logs. Instrument the PostgreSQL checkpoint boundary so both guest and private quiz transports report failures before their existing recovery handling. Emit JSON with operation, transport, opaque room reference, elapsed milliseconds and an allowlisted error category/code. Never emit SQL, raw exceptions, connection strings, checkpoint content, player names, answers, tokens or hashes. Rate-limit repeated events in bounded memory; logging failures must not change storage results. Warn on operations taking at least 250 ms, at most once per operation/transport per 30 seconds, and include suppressed counts on the next emitted event.

Use a small diagnostics helper at the existing store boundary, rather than duplicating log statements in each transport or adding a paid monitoring service. This preserves acknowledgement ordering, game rules, APIs and infrastructure. Test real store calls with injected database failures, slow completion, repeated errors and a failing log sink.

Add a bounded, opt-in Python WebSocket probe using the existing guest protocol. Use one isolated guest room with 2–20 simulated controllers, at most 20 inputs/sec each and at most 60 seconds of measurement. Measure frame arrival gaps, matching input-sequence echo latency, superseded inputs, ping RTT, joins, errors and disconnects using a monotonic clock. Keep credentials and player identifiers out of output. Run 10- and 20-controller samples on the existing Render URL; close all probe sockets afterwards. Record source/deployment identity and distinguish synthetic network evidence from physical phone, rendering and sustained-load acceptance. No new games, schema changes, resources or fees.

The live probe exposed valid in-flight controls reaching the server after heat results and producing `Unknown action.` errors. A follow-up three-controller production sample identified two such responses. Regression tests reproduce this in Grand Prix, Tap Dash and Light Trails. Route those matching-mode packets through their existing validators during reveal and ignore only otherwise valid, authorized controls for the same match/heat; preserve malformed-input, stale-match, impersonation and rate-limit rejection. This is a bounded reliability correction needed to complete the requested measurement, without changing game rules or points.
